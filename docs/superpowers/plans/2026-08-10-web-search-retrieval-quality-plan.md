# Sana 联网检索质量优化计划

日期：2026-08-10
状态：待评审

## 目标

解决当前联网查询召回不足、结果过旧、最终回复仍使用模型预训练知识的问题。

具体表现：

- 用户询问原神当前版本、最近角色和配队时，只召回 1 条结果。
- 查询头质量差，包含整段用户消息或噪音别名。
- 旧版本资料可能压过当前版本资料。
- 搜索结果不足时，模型仍会用自己的记忆补出版本号。

## 设计原则

- 不维护“当前/版本/角色/配对”这类关键词表。
- 查询规划和结果验证使用通用 LLM 结构化输出。
- 新鲜度评分使用通用时间与版本信号。
- 保持现有 Pipeline、心情策略和自主等级不变。

## Phase 1：查询规划

将现有 `WebQueryPlanner` 改为 LLM 驱动的短查询规划器。

### 输入

- 用户原文
- 解析后的实体
- 感知意图
- 当前时间
- 最大查询头数

### 输出

```json
{
  "queries": [
    {"type": "version", "query": "原神 当前版本 2026年8月"},
    {"type": "new_character", "query": "原神 最近新角色 2026"},
    {"type": "team", "query": "原神 当前版本 配队推荐"}
  ]
}
```

### 规则

- 每条查询不超过 60 字符。
- 不允许把整段用户消息直接作为查询。
- 除明显与时间无关的问题外，每条查询都带时间锚点。
- 查询头之间语义不同，避免重复搜索同一句话。
- LLM 规划失败时回退到“规范实体 + 截断后的用户问题”，不阻塞对话。

## Phase 2：多来源合并

修改 `WebSearchService.search()`，不再“一个来源有结果就停止”。

每个查询头并行尝试：

- 必应
- 百度
- 官网/百科直抓

即使必应已有结果，也继续收集百度和其他来源，最后统一交给 `RetrievalScorer` 去重合并。

每个来源：

- 尽量解析多条结果，而不是只留下 1 条。
- 返回 `query_head / title / url / snippet / source / fetched_at`。
- 单个来源失败只标记该来源，不中断整个查询头。

## Phase 3：新鲜度评分

在 `RetrievalScorer` 增加通用时间与版本信号。

从标题、摘要、URL 中提取：

- 年份：`2024 / 2025 / 2026`
- 版本号：`6.0 / 7.0 / v7.0`
- 日期词：`8月 / 08-04 / 2026-08`
- 相对时间词：`今日 / 最新 / 更新`

评分规则：

- 越接近当前时间，分数越高。
- 明确旧年份或旧版本的内容降权。
- 不写死“7.0 才对”，只比较“查询时间、结果时间、版本号”的通用关系。
- 每条结果增加 `freshness_score` 和 `freshness_note`，方便面板调试。

## Phase 4：结果验证与接地回复

新增 `ToolResultVerifier`，在第二次 LLM 生成前判断检索结果是否足够回答用户问题。

### 输入

- 原始问题
- 查询头
- 合并后的搜索结果

### 输出

```json
{
  "has_answer": true,
  "confidence": 0.4,
  "missing_facts": ["当前版本", "最近新角色"],
  "suggested_retry_query": "原神 7.0 版本 更新时间 2026"
}
```

### 行为

- 置信度低且尚未重试时，用 `suggested_retry_query` 再查一轮，最多 1 次。
- 重试后仍不足，标记 `low_confidence`，不再无限循环。
- 最终 LLM Prompt 增加 `[Grounding]` 约束：事实和时效问题只能基于注入结果回答。
- 结果没有答案时明确说“没查到可靠信息”，不得用训练记忆补版本号。
- `tool_trace` 增加 `retrieval_confidence`、`missing_facts`、`retry_count`。

## 测试计划

- 查询规划测试：给定“原神当前版本、最近角色、配队”和当前时间，生成至少 2 个语义不同的短查询，并包含时间锚点。
- 多来源合并测试：同一个查询头能合并必应、百度、官网直抓结果，不再只拿 1 条。
- 新鲜度评分测试：旧年份/旧版本结果被降权，当前年份结果优先。
- 结果验证测试：检索不足时最多重试一次；仍不足则标记 `low_confidence`，最终回复如实说明。
- 回归测试：原 43 个测试保持通过。

## 验收标准

- 用户询问当前版本、最近角色、配队时，能生成至少 2 个语义不同的短查询，并包含当前时间锚点。
- 同一个查询头能合并多个来源，不再只拿 1 条结果。
- 旧年份或旧版本结果会被降权。
- 检索不足时最多重试一次；仍不足则如实说“搜索没查到”。
- 最终回复不再用预训练知识补出旧版本号。
